Interview Agent Trace

The interviewer is not one chatbot but a small team: a script asks the main questions word for word, a safety agent screens every answer, a coder maps it, a probe agent decides whether to follow up, an interviewer agent writes the follow-ups and the reality check, and a bridge agent watches for a principle that clashes with a choice. Follow one participant through the team, then see how the same agents behave across 150 interviews.

Where the probe agent follows up, and whether it pays off

Follow-ups per 100 interviews by question. Dark part: the answer to the follow-up added a new consideration, a change to the map, or a reason that was missing.

The bridge agent: from check to reaction

Every interview is checked for a principle that clashes with a choice. Only the randomly assigned bridge arm is asked about it, so the bridge's effect can be estimated against the control arm.

Agent workload per interview

Why trace the agents? An AI interviewer is a measurement instrument. Recording which agent acted, when and why makes it auditable: one can check that probes are neutral, see where they add information, test whether the bridge question shifts later answers, and compare AI-led with human-led interviews. The same trace is produced for real interviews, where the probe and bridge decisions come from the LLM.

How it is computed. analysis/agent_trace.py builds the trace (recorded decisions for engine-run interviews, reconstructed for the hand-written personas); data/simulate_interviews.py runs the engine against simulated respondents; analysis/agent_report.py aggregates. Built by Tansif Anzar.
